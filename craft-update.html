적용 기록 · Before / After (누적 갱신)

제작 시스템 업데이트 — 로스트 인 블루2 대비 비교

"제작이 너무 엉성하다"는 피드백으로, 정리해둔 로스트 인 블루2 분석의 "적용 지점" 중 지금 코드로 바로 반영 가능한 항목들을 실제로 구현하고 있다. 그대로 베끼지 않고 우리 게임 사정에 맞게 다르게 튜닝한 부분을 항목별로 명시한다 — 새 변경이 생길 때마다 이 문서 하나에 계속 누적한다(별도 문서를 새로 만들지 않음).

2026-08-26 작성 · 2차 갱신(재료/도구) 문서 허브 참고한 분석 문서(원본, 미수정) 참고한 전체 목록(원본, 미수정) 로드맵(격차 항목 출처)
채집 노드 리스폰 조미료 레이어 동물 부산물 · 도구 티어 그대로 안 베낀 것 변경 파일 다음 후보

01 · 채집 노드

한 번 캐면 사라짐 → 자원별 시간차 리스폰

로드맵에 이미 "노드 리스폰 도입"이 미구현 항목으로 적혀 있었다 — LiB2의 "채집물마다 정해진 재생 시간이 있다"는 구조를 그 구현 형태의 선례로 삼았다.

Before

F로 캐면 scene.remove(g.node) + 배열에서 완전히 제거. 섬을 오래 돌아다닐수록 나무·돌·베리·섬유 자리가 하나씩 영구히 비었다.

→
After

모델은 씬에 남기고 visible=false + depleted=true로 숨김. 5초 주기 타이머가 자원별 리스폰 시간을 지난 노드를 다시 보이게 함 — 재로딩 없이 가벼움.

돌300초섬 전역
베리150초섬 전역

표류물(flotsam)은 리스폰 대상에서 제외

해변에 떠밀려오는 물병/사과/가족 유품 등은 이미 자체 스포너(주기적 랜덤 등장, 개수 상한)가 따로 있어서 그대로 영구 제거 방식을 유지했다 — 채집 노드와 표류물은 성격이 다르다고 판단.

02 · 조미료 레이어

고정 회복량 요리 → 조미료로 업그레이드하는 요리

LiB2는 조미료를 별도 "맛" 스탯으로 관리하지만, 우리는 그 개념만 가져오고 구현은 훨씬 단순화했다 — 새 UI 없이 기존 제작 메뉴에 상위 레시피로 얹는 방식.

기존 요리재료허기수분→ 조미 요리추가 재료허기수분
구운 생선물고기+불256소금구이 생선+소금 13410
구운 고기생고기+불300허브 스테이크+허브 1404
————허브차허브 2+베리 1422
허브차의 추가 효과

90초간 허기/수분 감소 속도를 25% 완화하는 버프가 붙는다 — 기존 "생존력 보양식"과 같은 버프 체계(status.buffMult)를 재사용, 새 시스템을 만들지 않았다.

기존 조리(굽기)를 대체하지 않고 그 위에 얹히는 구조라 "그냥 구워 먹기"도 여전히 유효한 선택지로 남는다 — 소금/허브가 없으면 못 먹는 게 아니라, 있으면 더 낫다.

03 · 동물 부산물 & 도구 티어

아이템/레시피 전체 목록을 다시 훑다가 발견한 죽은 레시피 3종

"아이템, 레시피 전체 목록에서도 유사하게 변경해달라"는 요청으로 카탈로그 문서의 재료 섹션을 다시 대조하다가 실제 버그를 하나 찾았다 — LiB2 분석이 새 기능 아이디어뿐 아니라 우리 코드의 구멍을 찾는 체크리스트로도 쓸모 있었던 사례.

발견한 버그 확인됨

leather_armor / leather_boots / leather_hat 레시피는 처음부터 leather/bone을 요구했지만, 이 두 재료를 얻는 경로가 사냥(meat만 드롭)·채집·표류물 어디에도 없었다 — 방어구 3종이 데모 출시 이후로 영구히 제작 불가능한 죽은 레시피였다.

Before

사냥하면 meat만 나옴. leather/bone은 ITEM_META와 레시피 원가에만 존재하고 세상 어디에도 실물이 없었다.

→
After

LiB2 재료 섹션의 "동물 부산물" 개념대로, 처치 시 종별 확률로 가죽/뼈가 같이 드롭. 방어구 3종이 실제로 크래프팅 가능해짐.

늑대270% 확률 1개50% 확률 1개
소490% 확률 2개40% 확률 1개
사슴360% 확률 1개50% 확률 1개

같은 참고 자료의 도구 섹션("자루에 돌촉·뼈촉을 달면 공격력 상승")도 함께 적용 — 새 무기를 처음부터 만드는 대신, 이미 만든 창을 재료로 소모해 업그레이드하는 레시피로 구현했다. axe→iron_axe와 같은 기존 티어링 패턴을 그대로 재사용.

04 · 원본과 다르게 만든 지점

"유사하게"이지 "그대로"가 아닌 이유

항목로스트 인 블루2 원본환장의 아일랜드 버전
조미료 조작 방식 요리 시 조미료를 넣는 전용 "맛" 스탯/조리 단계 단순화 완성된 요리+조미료 → 상위 아이템으로 만드는 별도 레시피 (새 UI 불필요)
재생(리스폰) 수치 자원별 실측 재생 시간표(원문 그대로의 구체적 수치) 임의 산정 우리 게임의 기존 밸런스(허기/수분 감소 속도, 세션 길이)에 맞춰 150~300초 사이에서 새로 정함 — LiB2 수치를 그대로 옮기지 않음
자원-지역 분리 거점 3곳(동굴/초원/해변)이 자원 접근성으로 갈림 개념만 채택 거점은 이미 "1채만"으로 단순화하기로 결정된 상태라, 대신 채집물 2종(소금=해안/허브=내륙)만 지역으로 가름 — 거점 자체는 안 늘림
동물 부산물 드롭 부위·희귀도별로 세분화된 사냥 드롭 표 단순화 종당 가죽/뼈 확률 하나씩만 — 정교한 표 대신 "죽은 레시피를 살릴 만큼만" 구현
도구 성능 강화 자루+촉(돌/뼈) 조합을 자유롭게 선택하는 제작 트리 단순화 완제품(창)을 소모해 상위 무기로 바꾸는 단방향 업그레이드 레시피 하나
날씨 → 자원 스폰 날씨 이벤트 다음날 특수 자원 등장 이번엔 보류 로드맵에 격차로 남아있던 항목, 이번 턴 범위 밖 — 아래 "다음 후보" 참고

05 · 변경 파일

코드가 실제로 바뀐 곳

src/state.jssalt/herb/seasoned_fish/seasoned_meat/herb_tea/bone_spear ITEM_META, 조미료 레시피 3종+뼈창 레시피, FRESH_LIMIT에 herb 추가
src/world.jsscatterProps()에 소금(해안 밴드)·허브(내륙) 채집 노드 스캐터 추가
src/main.jsRESPAWN_SECONDS 테이블, F키 채집 핸들러(제거 대신 숨김+타이머), findNearestGatherable에 depleted 필터, animate()에 5초 주기 리스폰 틱, 처치 메시지에 부산물 드롭 반영
src/wildlife.jsSPECIES 테이블에 종별 가죽/뼈 드롭률 추가, takeDamage() 사망 분기에서 드롭 굴림
src/player.jsHELD_ITEM_MODELS에 뼈창(spear.fbx 재염색) 등록, 처치 메시지에 부산물 텍스트 합성
ASSETS.md소금/허브/뼈창의 재염색-재사용 출처 기록
검증 방법

헤드리스 크롬(CDP)으로 실제 게임을 띄워 확인: ① 소금 노드 채집 → 인벤토리 반영+노드 숨김, ② respawnAt을 과거로 되돌려 5초 리스폰 틱이 실제로 노드를 되살리고 재채집도 가능함을 확인, ③ 조미료 레시피 3종 재료 소모/결과물 생성 확인, ④ 야생동물 9마리를 전부 처치시켜 종별 가죽/뼈 드롭 확인, ⑤ 확보한 재료로 뼈창·가죽 갑옷·가죽 신발·가죽 모자 4개 레시피 모두 craft() 성공 확인(이전엔 재료 부족이 아니라 재료 자체가 존재하지 않아 항상 실패). 콘솔 에러 0건.

06 · 다음 후보

분석 문서에 있었지만 아직 안 건드린 것

  • 날씨 → 자원 스폰 연동 — 비/폭풍 다음날 특정 노드 스폰율을 올리는 식으로, 기존 weather 시스템에 얹을 수 있음.
  • 가구 우선순위 명시 — 이동식 집 레벨마다 "왜 좋은지"를 UI 텍스트로 붙이는 것. 코드보다 카피 작업에 가까움.
  • 온천 · 취침 전 동료 부탁 — 둘 다 동료 시스템 전제라 1막(동료 비활성) 범위 밖. 동료가 다시 켜지는 시점에 재검토.
  • 원거리 무기(활/새총)의 실제 데미지 — 이번 조사 중 발견한 별도 갭: 현재 화살/새총은 명중해도 데미지 판정이 아예 없는 순수 연출(발사 애니메이션+탄약 소모만)이라, 뼈촉 화살 같은 조미료식 업그레이드를 만들어도 의미가 없어 이번엔 손대지 않음 — 원거리 전투 자체가 먼저 구현돼야 할 별개 이슈로 남겨둠.
